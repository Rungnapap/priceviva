# PriceViva v0.5 — audit and implementation plan

Status: **proposed, waiting for approval and the background images** (25 Oct 2026).

## 1. Audit of v0.4

### Works today (tested in the sandbox)
- **Text search:** typo tolerance, synonyms, exact barcode (GTIN) lookup, filters and sorting, and autocomplete. Live mode uses PostgreSQL full-text and trigram search.
- **Product pages:** gallery, specs, offers ranked by delivered total (item + shipping + import), each cost marked verified, estimated or unknown, and "last confirmed" times in live mode.
- **Grouping:** offers are grouped only on GTIN + condition, or brand + MPN + colour + size + condition. Sizes, colours and conditions are never merged.
- **Compare:** side by side, up to 3 products of the same type.
- **Favourites and shopping area:** stored in the browser only.
- **Awin importer and admin:** feeds, import runs, data quality. Tested on synthetic fixtures, never against a real Awin account.
- **Price observations:** recorded on every live import. No chart reads them yet.
- **Store links:** "Visit store" through the allow-listed `/go/` redirect.

### Demonstration only, or not built yet
- Offers in test and demo mode are "Sample Shop" or fictional data.
- Local Deal Radar stores and promotions are fictional.
- **Price alerts and price history:** honest "coming soon" pages only. No email sending, accounts or charts.
- **Retailer pages:** only a single `/stores` overview; there are no per-retailer pages.
- **Not built:** recently viewed, saved searches, back-in-stock alerts and accounts.
- **No rate limiting** on the public API routes (`/api/products`, `/api/search/suggest`).
- **Product photos:**
  - demo mode: drawn illustrations;
  - test mode: DummyJSON photos (no licence; fine for private testing only);
  - live mode: retailer feed images.

## 2. Photo search — proposed architecture

| Step | How | Runs where |
|---|---|---|
| 1. Upload and preprocessing | Dialog with upload, camera (`capture` file input plus `getUserMedia` where allowed), drag-and-drop, preview and crop. Checks JPEG/PNG/WebP, max 8 MB, shrinks to max 1024 px and strips location data by re-encoding on a canvas | Browser |
| 2a. Barcode reading | `BarcodeDetector` API (Chrome/Edge/Android), with a small WebAssembly fallback (zxing) for Safari/Firefox | Browser |
| 2b. Image embedding | CLIP image model (ONNX, quantised), so only a 512-number vector leaves the device | Browser, or a server route if the device is too slow |
| 3. Candidate retrieval | Barcode → exact GTIN lookup. Vector → nearest catalogue images with `pgvector` (free extension in Supabase), or an in-memory index in test mode | Server |
| 4. Exact-match check | "Exact product match" **only** when a barcode matches a GTIN, or the user confirms brand + model that match exactly | Server |
| 5. Ranking | Visual similarity combined with text search (detected text, brand, category). Labels: **Exact match / Likely match / Visually similar** | Server |
| 6. Results UI | Same result cards as text search plus a match badge, "why this result" and the cropped photo | Browser |

- **Privacy:**
  - by default, photos never leave the device; only the barcode number or the vector is sent;
  - nothing is stored;
  - rate limits: 10 photo searches per minute per IP, plus a request size cap.
- **Indexing:** catalogue images are embedded when products are imported, through a new import step and an admin "re-index" button.
- **Costs:** no paid service needed. The browser model is roughly 90 MB, downloaded once and cached. Phones on slow networks may wait, so a server-side option is documented.
- **Paid alternative, documented only and not built unless you ask:** an external vision API (e.g. a cloud product-recognition service). It sends user photos to a third party and costs per request. I will check current prices and terms before recommending any.
- **Honest limits:**
  - Demo-mode illustrations can't be matched to photos, so photo search is disabled there and the page says so.
  - In test mode it works against DummyJSON photos.
  - Visual similarity alone never produces "exact match".

## 3. Phases

1. ✅ Audit and plan (this document).
2. **Backgrounds, homepage and design system.** Needs your images.
   - Calmer, lower hero.
   - Smaller headings and fewer translucent boxes.
   - One clear message: "Search for a product, compare retailer offers, and discover local or international choices."
   - Camera icon in the search bars (opens the dialog in phase 3).
   - **Stop here and show you the homepage.**
3. Photo-search dialog: upload, camera, drag-and-drop, crop, replace, errors.
4. Visual-search backend: barcode path, embedding interface, test-mode index, rate limits, and an honest "unavailable" state when the model or index is missing.
5. Search results and comparison:
   - match badges and filters on mobile;
   - offer table with country, condition, availability and updated time;
   - "alternative products" separated from exact matches.
6. Return visits:
   - recently viewed and saved searches (browser storage);
   - watchlist;
   - price history charts when real observations exist (live mode only);
   - alerts architecture (Supabase Auth + email provider) documented, with nothing sent until it is connected.
7. Responsive and accessibility pass across all pages, plus Local Deal Radar polish.
8. Typecheck, tests and browser checks here. `npm run check` (lint and production build) on your PC.
